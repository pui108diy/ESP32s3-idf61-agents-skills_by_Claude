# SKILL.md — Router · esp32s3-idf61 · v0.4-draft

## 1. ใช้เมื่อ
- ผู้ใช้ขอโค้ด/แก้โค้ด/อธิบาย API ของ ESP32-S3 บน ESP-IDF v6.1
- ผู้ใช้ถามว่า API/macro/ขา ใช้ได้หรือไม่บน S3

## 2. ไม่ใช้เมื่อ
- ชิปอื่น (ESP32, S2, C3, ...) หรือ IDF เวอร์ชันอื่น: แจ้งผู้ใช้ว่า reference นี้ใช้กับ S3 + v6.1 เท่านั้น แล้วตรวจด้วยแหล่งตรงชิป/เวอร์ชัน

## 3. ขั้นตอน (ทำตามลำดับ)
1. อ่าน `PROTOCOL.md` ส่วน A (ป้ายหลักฐาน, gate)
2. ระบุงาน แล้วดูตาราง Dependency Map (ข้อ 4) เพื่อเลือก reference และ Hot-List
3. โหลด reference และ Hot-List ของกลุ่มนั้นเท่านั้น (ไม่โหลดทั้งหมด)
4. ถ้าสิ่งที่ต้องใช้ไม่อยู่ใน reference หรือเป็น [UNV]: ตรวจจาก `evidence/<api>-evidence.md` และ header ใน RAG ก่อน แล้วค่อยเว็บ ([WEB])
5. เขียนโค้ด พร้อม CMakeLists.txt เมื่อสร้างโปรเจกต์ใหม่
6. รัน Gate (PROTOCOL.md A.4) และ checklist Hot-List
7. ตอบพร้อมแหล่งที่มา (ข้อ 5)

## 5. รูปแบบคำตอบ
- ตอบภาษาเดียวกับผู้ใช้
- ทุกข้อเท็จจริงมีป้ายหลักฐาน และแยกชัดว่าส่วนไหนมาจาก RAG (ฐานข้อมูล) ส่วนไหนมาจากเว็บ ([WEB] + ลิงก์) ส่วนไหนเป็นอนุมาน ([INF])
- โค้ดต้องมี `#include`, CMakeLists (เมื่อเป็นโปรเจกต์), และสถานะ [BUILD]/[HW]
- ท้ายคำตอบมี "ที่ยังไม่ได้ตรวจ" ถ้ามี

## 6. กฎเหล็ก
- ห้ามเดา signature/macro/ค่า default
- ห้ามใช้ข้อ [UNV] และ [GLM] เป็นข้อเท็จจริงในโค้ดส่งมอบ
- ห้ามรีนัมเบอร์รหัส Hot-List
- ครอบ API ที่ขึ้นกับ capability ด้วย `#if SOC_*`
